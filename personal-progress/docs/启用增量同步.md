# 启用按日期和模块的增量同步

网站已兼容两种数据库状态。未升级时，原有账号和保存方式继续可用，并在刷新后复用本机历史缓存；升级后，日记按日期、其他记录按存储项传输变化和删除，不重复传输未改动的历史正文或图片链接。

## 在现有 Supabase 项目执行一次

1. 使用项目管理员账号打开 [SQL Editor](https://supabase.com/dashboard/project/bjrkcxapudlsgslmaxow/sql/new)。
2. 打开本项目 `supabase/migrations/20261119_incremental_record_sync.sql`，复制全文到 SQL Editor。
3. 点击 **Run**，等待成功提示。脚本使用事务，只增加函数和相应权限；不删除数据、不改账号，也不改变原有记录表和备份机制。脚本可以重复执行。
4. 刷新手机和电脑的网站页面，登录同一账号。页面会自动识别新接口，继续使用原有记录。

如项目仍提示 `exceed_egress_quota`，需先由管理员恢复 Supabase 服务额度；升级脚本不能解除计费限制。

## 确认是否启用

打开浏览器开发者工具的 Network 面板，筛选 `daily_space`。启用后会出现 `daily_space_read_changes` 和 `daily_space_write_changes` 请求；手机直连失败时，这些请求通过网站的 `/api/record-sync?rpc=...` 转发，仍使用本人的登录令牌。

初次在新设备登录需要下载已有记录。后续检查无变化时只返回版本信息；修改一篇日记只上传该日期内容和同步元数据。图片本体仍按浏览器缓存情况下载，新增照片仍上传到原图片存储。

未升级数据库时，不会报错阻止日常保存，但远端发生变化后仍需读取原整份记录；完整增量同步必须执行上述 SQL。

## 本地回归验证

```powershell
node scripts/check-storage-regressions.cjs
# @electric-sql/pglite 可安装在临时目录，无需加入网站的生产依赖。
$env:PGLITE_MODULE = '<临时目录>/node_modules/@electric-sql/pglite'
node scripts/check-incremental-sync.cjs
```

测试覆盖原有历史数据、单日期同步、刷新缓存、并发编辑与删除、旧客户端和飞书写入、账号隔离，以及数据库未升级时的兼容保存。
